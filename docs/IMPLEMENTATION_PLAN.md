# JobFinderKZ — полный план реализации

Уточнение пользователя от 2026-09-17 (имеет приоритет над исходным пунктом ниже): пользователь не должен добавлять вакансии. Пользовательский интерфейс получает их из подключённого источника; ручная форма удалена, служебный метод создания доступен только администратору. Также требуются выразительная типографика и корректное распределение CV по полям вместо всего текста в «О себе».

## 1. Цель, первая версия и принятые решения

Создать веб-сервис: **регистрация → загрузка CV → подходящие вакансии → сопроводительное письмо и адаптация CV → подготовка → тренировочное интервью → разбор и статистика**.

План объединяет первоначальную функциональность, PostgreSQL с pgvector и получение базы вопросов из видеоинтервью на YouTube.

| Параметр | Решение |
|---|---|
| Аудитория | IT-специалисты Казахстана и СНГ, включая ищущих зарубежную работу |
| Первые направления | Frontend, Python backend, QA |
| Уровни | Junior и middle |
| Формат | Веб-приложение |
| Языки | Русский интерфейс; CV, письма и интервью на русском или английском |
| Первый запуск | Локальный прототип для владельца и нескольких тестовых пользователей |
| Бюджет ИИ | До $20 в месяц на приложение |
| Источники вопросов | Прежде всего опубликованные видеоинтервью; документация и статьи для проверки и дополнения |
| Объём видео | До 20 часов в месяц, дополнительно ограниченных бюджетом |
| Голос | Запись и отправка ответа по очереди |
| Монетизация | Последующий этап; учёт использования закладывается сразу |

Основные решения приняты. Сначала проверить импорт нескольких реальных видео: от качества процесса зависит главная база знаний продукта.

## 2. Пользовательские функции

### Регистрация и личный кабинет
- Email, пароль, вход и выход.
- Профиль: направление, уровень, желаемые регионы, формат работы и язык интервью.
- Доступ к резюме, вакансиям, документам, подготовке и истории тренировок.
- Удаление аккаунта и связанных пользовательских данных.
- Роль администратора для источников и вопросов.

### Загрузка и обработка CV
- DOCX и PDF с текстовым слоем. Для сканов без текста — ручная вставка.
- Извлечение опыта, навыков, образования, проектов и языков.
- Проверка и исправление результата пользователем.
- Подтверждённый профиль — источник фактов для вакансий и документов.
- Хранение исходного резюме и версий.

### Подбор вакансий
- Первый автоматический источник — HeadHunter через авторизованный API; нужна регистрация приложения: https://dev.hh.ru/.
- Ручное добавление описания и ссылки с любой площадки, включая зарубежные.
- Фильтры: регион, направление, уровень, формат работы.
- До 20 отобранных вакансий на ИИ-ранжирование.
- Причины соответствия, совпадающие навыки и недостающие требования.
- Избранное, оригинальные ссылки, предотвращение дублей.
- Состояние подключения и дата сохранённых результатов при недоступности источника.

### Сопроводительные письма и адаптация резюме
- Генерация по запросу для выбранной вакансии.
- Адаптация акцентов, структуры и формулировок CV.
- Запрет на добавление отсутствующих навыков, работодателей, стажа и достижений.
- Предпросмотр изменений, редактирование, копирование и экспорт DOCX.
- Отклик отправляет пользователь на площадке.
- «Рекомендательное письмо» означает сопроводительное письмо кандидата.

### План подготовки
- Семидневный план по требованиям вакансии и пробелам профиля.
- Темы, материалы, вопросы, примеры ответов, практические задания.
- Отметки выполнения.
- Только опубликованные вопросы и проверенные материалы базы знаний.

### Тренировочное интервью
- Выбор вакансии, направления, уровня, языка. Пять вопросов.
- Текст или запись до трёх минут на каждый ответ.
- Проверка и подтверждение расшифровки перед оценкой.
- Правильность, полнота и обоснование: шкала 0–4.
- Ошибки, пропуски, улучшенный пример ответа и ссылки на материалы.
- Принимать разные корректные формулировки, не сравнивать только с эталонным текстом.
- При недостаточных или противоречивых основаниях сообщать, что надёжная оценка невозможна.
- Практические задания принимаются текстом/кодом без выполнения кода.
- Незавершённую сессию можно продолжить.

### История и статистика
Хранить вопросы, ответы, оценки, обратную связь и версии критериев. Динамика внутри направления и уровня, слабые темы, повторяющиеся ошибки. Произношение и акцент не влияют на техническую оценку.

## 3. База вопросов из YouTube и других материалов

### Получение текста
Администратор добавляет отдельную опубликованную запись. Нормализовать YouTube ID и исключать повторный импорт.
1. youtube-transcript-api: сначала авторские субтитры исходного языка, затем автоматические.
2. При технической несовместимости — субтитры через yt-dlp.
3. При отсутствии субтитров — доступная аудиодорожка и распознавание.
4. Некачественную расшифровку можно заменить распознаванием аудио по действию администратора.
5. При блокировке/недоступности — ручная загрузка аудио, видео, TXT/SRT/VTT.

Неофициальные способы не гарантируют доступ: https://github.com/jdepoix/youtube-transcript-api и https://github.com/yt-dlp/yt-dlp. Обрабатывать изменения YouTube и блокировки. Официальный API подходит для субтитров видео с правами на редактирование; авторские каналы — позднее: https://developers.google.com/youtube/v3/docs/captions/download.

### Распознавание и хранение
- gpt-4o-transcribe-diarize: текст, интервалы, говорящие (https://developers.openai.com/api/docs/guides/speech-to-text#speaker-diarization).
- Длинные записи делить с сохранением смещений и устранением повторов на границах.
- Метки говорящих разных частей автоматически не отождествлять.
- Роли кандидата/интервьюера определять по контексту, неоднозначности передавать администратору.
- Хранить исходную/обработанную расшифровки, язык, способ, источник, таймкоды.
- Удалять временное аудио после успешного сохранения.
- faster-whisper — возможное последующее расширение.

### Извлечение вопросов
Расшифровка → тематические фрагменты → вопросы и обсуждения → проверка → публикация.
Для обсуждения извлекать основной вопрос, уточнения, ответ кандидата, замечания интервьюера, практическое условие (если присутствует), тему, предполагаемый уровень, интервал.
Ответ кандидата и эталон хранить отдельно. Эталон и критерии опирать на техническую документацию и проверять перед публикацией. Если условие только на экране или контекст потерян — требовать ручного дополнения, не угадывать детали.

### Проверка и публикация
- Экран видеоисточника, расшифровки и карточек.
- Правка формулировок, ролей, тем, уровней, эталонов, критериев.
- Объединение похожих вопросов с сохранением всех исходных обсуждений.
- Ссылки на моменты видео для каждого опубликованного вопроса из видео.
- Импорт выбранных страниц документации и статей из разрешённого списка.
- Цель: 90 проверенных вопросов, по 30 на направление, junior и middle.
- RAG по проверенным материалам для подготовки и оценки; без обучения своей модели.

## 4. Техническая реализация

### Архитектура и данные
- React, TypeScript, Vite.
- FastAPI, Pydantic, SQLAlchemy, Alembic.
- PostgreSQL 18 с pgvector через Docker Compose.
- Закрытое локальное файловое хранилище.
- Отдельный Python worker; очередь в PostgreSQL.
- FFmpeg, yt-dlp, yt-dlp-ejs, Deno, youtube-transcript-api; версии фиксируются после контрольных записей.
- Хранить аккаунты, версии CV, вакансии, документы, планы, интервью, ответы, оценки, источники, расшифровки, фрагменты, вопросы, расходы.
- Гибридный полнотекстовый/векторный поиск с фильтрами языка, направления, уровня. Отдельная векторная БД не нужна: https://github.com/pgvector/pgvector.

### API и задания
REST /api/v1 для аккаунтов, CV, вакансий, документов, подготовки, интервью, статистики; административные методы для импорта, расшифровок, публикации.
Длительные операции возвращают job_id; GET /jobs/{id}.
Очередь: промежуточные результаты, восстановление после перезапуска, ограниченные повторы, отсутствие повторной обработки завершённых этапов, защита от параллельного выполнения. Не повторять автоматически платный запрос с неизвестным после сбоя результатом без учёта возможного списания.

### Модели и расходы
- gpt-5.4-mini: профиль, документы, вопросы, оценка.
- gpt-4o-mini-transcribe: короткие ответы.
- gpt-4o-transcribe-diarize: интервью.
- text-embedding-3-small: поиск.
- Конфигурируемые модели и серверная проверка структурированных ответов.
- Учёт всех этапов, резервирование перед запросом с учётом параллельных задач.
- Месячный лимит $20: приостанавливать новые платные операции. Сохранённые результаты доступны без повторных вызовов.

### Защита данных
Argon2; HttpOnly-cookie и защита изменяющих запросов. Проверка владельца каждого объекта и роли администратора. Ключи только на сервере. Исключать ненужные контактные данные из ИИ-запросов. CV, вакансии, источники — недоверенные данные, инструкции внутри не управляют системой. Импорт URL только из публичных разрешённых адресов.

## 5. Этапы, проверки и переход к работе

| Этап | Результат |
|---|---|
| 1 | Полный план в docs/IMPLEMENTATION_PLAN.md; прогресс и запуск в docs/PROGRESS.md |
| 2 | Python, Docker, frontend/backend, PostgreSQL, миграции, аккаунты, роли |
| 3 | Реальные видео: текст → вопросы → административная проверка |
| 4 | Источники, поиск, дедупликация, публикация, наполнение |
| 5 | CV, подтверждение, HeadHunter, ручные вакансии, ранжирование |
| 6 | Письма, адаптация CV, экспорт, семидневный план |
| 7 | Текстовая оценка, микрофон, продолжение, статистика |
| 8 | Полный сценарий, расходы, восстановление, инструкции |

При первоначальной проверке Python не найден в PATH, Docker daemon недоступен. Подготовка окружения входит в технический этап.

Проверки:
- Авторские/автоматические субтитры и их отсутствие.
- RU/EN, несколько говорящих, длинные записи, границы частей.
- Ошибочный ответ с исправлением интервьюера, неполное условие на экране.
- Блокировки, ручные файлы, восстановление.
- Нет дублей и повторной оплаты завершённых этапов.
- CV/документы без выдуманного опыта.
- Корректные, перефразированные, частичные и неверные ответы RU/EN.
- Микрофон Chrome/Edge; текст при отказе.
- Изоляция аккаунтов, удаление, бюджет при параллельности.
- Полный путь до статистики после повторного входа.

pytest и Playwright с фиксированными внешними ответами; реальные интеграции отдельно с ключами в пределах бюджета.

После первой версии: зарубежные площадки, Telegram, новые видео, анализ изображения/экранного кода, прямые эфиры, разговорные интервью, публичный запуск, тарифы.

Следующее действие: реализация этапов по порядку. Дополнительное проектирование не требуется.

Речь и embeddings пока используют отдельный ключ OpenAI. Gemini Free предназначен для тестов с вымышленными данными. Модель 3.5 Flash-Lite выбрана после реального отказа 2.5 для новых пользователей.
